# obilet-mcp 🇹🇷

mcp-name: io.github.mohammad-abbasi-sh/obilet-mcp

سرور MCP غیررسمی و **فقط‌خواندنی** برای **obilet.com**، جست‌وجوی بلیط
اتوبوس و پرواز ترکیه — جست‌وجوی مکان‌های اتوبوس، فهرست همه‌ی سفرهای
اتوبوس یک مسیر + تاریخ (شرکت، نوع اتوبوس، صندلی، ساعت حرکت/رسیدن، مدت،
قیمت به لیر، امتیاز شرکت، توقف‌ها)، خواندن جزئیات کامل سفر، گرفتن آمار
قیمت، و خواندن خلاصه‌ی پرواز (تعداد پرواز، کمترین/بیشترین قیمت،
ایرلاین‌ها) برای همان جفت شهر.

> ساخته‌ی محمد عباسی در چارچوب «کارخانه‌ی MCP ترکیه» (به سبک سپهر). هیچ
> وابستگی‌ای به obilet.com ندارد.

## برای ایجنت‌های هوش مصنوعی

به پیکربندی MCP client خود اضافه کنید (stdio):

```json
{
  "mcpServers": {
    "obilet": {
      "command": "uvx",
      "args": ["obilet-mcp"]
    }
  }
}
```

یا به‌صورت محلی اجرا کنید: `python -m obilet_mcp.server`
(نیازمند `mcp<2` و `curl-cffi`).

## ابزارها

| ابزار | توضیح |
|------|-------|
| `obilet_search_locations` | جست‌وجوی مکان با نام — `query` (مثل «Ankara» یا «İstanbul»)، `kind` (‏«bus» / ‏«flight»)؛ برمی‌گرداند: شناسه، نام، نام نمایشی، شناسه‌ی شهر (شناسه‌های اتوبوس عدد و شناسه‌های پرواز رشته‌ای مثل «250_0» هستند) |
| `obilet_search_bus_journeys` | سفرهای اتوبوس یک مسیر + تاریخ — `origin_id` / `destination_id` (شناسه‌های مکان اتوبوس، مثل ۳۴۹ استانبول اروپا ← ۳۵۶ آنکارا)، `date` به صورت «YYYY-MM-DD»، `sort` (‏«price_asc» / ‏«departure» / ‏«duration»)، `limit` از ۱ تا ۲۴؛ فیلترها: `offset` (≥ ۰)، ‏`after` / ‏`before` (بازه‌ی ساعت حرکت «HH:MM»)، ‏`destination_terminal` (بخشی از نام ایستگاه مقصد، مثل «Aşti»)، ‏`min_seats`، ‏`min_rating` (۰ تا ۱۰)؛ برمی‌گرداند: شناسه‌ی سفر، شرکت، نوع اتوبوس، صندلی، ایستگاه‌ها، ساعت حرکت/رسیدن، مدت، قیمت به لیر، امتیاز شرکت (۰ تا ۱۰)، توقف‌ها، به‌علاوه‌ی تعداد کل و تعداد فیلترشده |
| `obilet_journey_detail` | جزئیات کامل یک سفر (`journey_id`): شرکت، نوع اتوبوس، صندلی، ایستگاه‌ها، ساعت حرکت/رسیدن، مدت، قیمت اینترنتی و قیمت اصلی (لیر)، هزینه‌ی خدمات، امتیاز شرکت، نام اتوبوس، سکو (پرون)، توضیح، و ساعت هر توقف |
| `obilet_price_stats` | آمار قیمت برای یک مسیر + تاریخ: تعداد سفر، کمترین / میانه / میانگین / بیشترین قیمت بلیط (لیر)؛ ‏`sampling`: ‏«first» (همه‌ی سفرها، پیش‌فرض) یا «day» (ارزان‌ترین سفرها + یک سرویس در هر بازه‌ی ۲ ساعته‌ی روز) |
| `obilet_flight_summary` | خلاصه‌ی پرواز برای یک مسیر + تاریخ: تعداد پرواز، کمترین/بیشترین قیمت (لیر)، کمترین/بیشترین مدت، اولین/آخرین حرکت، پرچم پرواز مستقیم، ایرلاین‌ها با کد یاتا (فهرست تک‌تک پروازها در نسخه‌ی ۱ نیست — اندپوینت زنده‌ی فهرست پرواز ۴۰۴/۵۰۰ برمی‌گرداند) |
| `obilet_health` | بررسی سلامت: یک درخواست به صفحه‌ی اصلی obilet.com — برمی‌گرداند وضعیت «ok» / ‏«blocked» / ‏«error»، کد HTTP، آدرس و توضیح |

نمونه‌ی خروجی (`obilet_search_bus_journeys` / استانبول اروپا ← آنکارا، ۲۰۲۶-۱۱-۰۷):

```json

 "sort": "price_asc", "total": 421, "count": 2, "journeys": [
  {"journey_id": 1432053091, "partner": "Yükseller Aksaray Birlik",
```

## چطور کار می‌کند؟

سایت obilet.com یک API از نوع JSON دارد اما نشست‌محور است: اول یک
صفحه‌ی HTML گرفته می‌شود (کوکی‌های `ob_Session` و `__cf_bm` را می‌گذارد)،
بعد POSTها با `X-Requested-With: XMLHttpRequest` و همان صفحه به‌عنوان
Referer فرستاده می‌شوند. مکان‌ها: POST به ‎/json/duraklar (اتوبوس) یا
‎/json/ucak-duraklari (پرواز). سفرها: POST به
‎/json/journeys/{مبدأ}-{مقصد}/{تاریخ} با `{}` — یک پاسخ همه‌ی سفرهای
مسیر را دارد. جزئیات: POST به ‎/json/sefer-tam/{journeyId}. همان پاسخ
سفرها خلاصه‌ی پرواز (flightSummary) را هم دارد. مرتب‌سازی سمت کلاینت
است (قیمت / ساعت حرکت / مدت). اندپوینت پروازهای ناهمگام سمت سایت خراب
است (۴۰۴/۵۰۰)، پس فهرست تک‌تک پروازها بیرون از محدوده‌ی نسخه‌ی ۱ است.
انتقال از نشست پایدار curl-cffi با چرخش پروفایل استفاده می‌کند
(chrome120 ← chrome131 ← safari17_0، چسبنده روی آخرین پروفایل
سالم): با خطای HTTP ‏۴۰۳/۴۲۹ نشست با پروفایل بعدی بازسازی و دوباره
پرایم می‌شود و درخواست یک بار تکرار می‌شود، بعد خطای مشخص برگردانده
می‌شود (دیوار ربات ۴۰۳ / محدودیت نرخ ۴۲۹ / یافت نشد ۴۰۴). کش کوتاه
۱۲۰ ثانیه‌ای پرایم از گرفتن تکراری صفحه‌ی HTML برای همان صفحه جلوگیری
می‌کند. درخواست‌ها با فاصله‌ی حدود ۰٫۸ ثانیه فرستاده می‌شوند؛ همه‌چیز
فقط‌خواندنی است، بدون لاگین و بدون کلید API. هر خروجی ابزار
`fetched_at` ‏(UTC)‏، ‏`source="obilet.com"` و سلب مسئولیت داده‌ی
غیررسمی را دارد. تست دود زنده‌ی روزانه
(`.github/workflows/smoke.yml`، ساعت ۰۶:۰۰ UTC) صفحه‌ی اصلی را با
`obilet_health` بررسی می‌کند تا خرابی سایت/انتقال پیش از کاربران
دیده شود.

## نصب

```bash
uvx obilet-mcp==0.1.0        # اجرای مستقیم (نیازمند uv)
# یا
pip install obilet-mcp==0.1.0
obilet-mcp         # اجرای سرور MCP روی stdio
```

## تست‌ها

```bash
python -m venv .venv && .venv/bin/pip install -e .
.venv/bin/python -m unittest discover -s tests -v
```

تست‌های آفلاین روی نمونه‌های ضبط‌شده از صفحه‌های واقعی اجرا می‌شوند
(دریافت‌شده در ۲۰۲۶-۱۱-۰۶)؛ تست‌های زنده به obilet.com وصل می‌شوند.
